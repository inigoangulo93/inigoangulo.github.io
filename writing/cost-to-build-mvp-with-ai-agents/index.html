How much does it cost to build an MVP with AI agents? Real numbers from one build

Inigo AnguloNovember 4, 20266 min readProduct and consulting
In this series: Product and consulting
  • Fractional product manager vs product consultant: which one do you actually need?

Everyone asks the same question in the first call: what does it cost? Here is what one build cost, with the caveat that it was a build I ran end to end for one client, so the human time was mine and the decisions were fast. Treat the numbers as an honest floor, not a quote. The method that produced them is in how to build an MVP with AI agents.

7 weeksfrom first commit to 15 releases in production
~CHF 300per month in agent usage, passed through at cost
~CHF 60per month in hosting, database and monitoring at MVP scale
1 personscoping, deciding, approving. Zero engineers on payroll

Where the money does not go

Not to writing code. That is the part that collapsed. 445 pull requests in seven weeks with an agent bill in the low hundreds of francs a month. Infrastructure at MVP scale is a rounding error: a hosted Postgres with auth and storage, a frontend host, error tracking. All on plans that cost less than a lunch in Zurich.

Where it goes

  1. Scoping. Week one was spent on what the product must do, what it must never do, the data model and the security boundaries, written as tickets with acceptance criteria. This is the week that decides whether the following six produce a product or a pile of features. It is human time, and it is the most expensive line.
  2. Deciding. Agents stop at every real decision and ask. Over seven weeks that was more than 170 recorded decisions, each answered in seconds because the format is fixed, but each requiring someone who knows what the product is for. You cannot outsource this to the agents without getting their guess.
  3. Verification. Reading what the gates say instead of trusting their colour, opening the deployment by URL, running the pen test before every release. This is what separates a demo from something you can put a customer on. It is a fixed cost per release, which is why the releases are batched into numbered sets instead of shipped one by one.
  4. Design. A brand, a token system, 26 components. Agents built the components from the tokens; the taste and the decisions were human. Skipping this is how MVPs end up looking like every other agent built app, which customers notice.

How to read a quote

When I quote a build for a client, the first version is a fixed price for a sprint of two to six weeks, with the agent costs passed through at cost. What varies the price is almost entirely scope clarity: a client who can say what the product must never do saves a week. A client who wants to find out by building pays for the finding out, which is a legitimate thing to pay for, but it should be called that.

What should make you suspicious: a quote that is mostly "development hours". If the building is being done by agents, the hours that matter are scoping, deciding and verifying, and an honest quote says so.

What you get for it

Real code in a repository you own, with tests, a release process and a decision log, that any engineer can continue. Not a prototype on a no code platform and not a chat transcript. The Acervo case shows the artefacts: the data model, the promotion flow, the evidence from the CI record.
